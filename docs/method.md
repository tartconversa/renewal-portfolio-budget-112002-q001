# 测算口径与规则说明

本文件解释工具如何把输入表转换为可复核的年度安排，以及哪些判断是工具做的、哪些必须由专班确认。

## 1. 有效成本

| 口径 `cost_basis` | 取值 |
| --- | --- |
| `confirmed`（默认） | 优先使用 `confirmed_cost`；缺失时退回 `estimate`，并标记 `unconfirmed` |
| `estimate` | 使用 `estimate`；与核定值不一致时标记 `unconfirmed` |
| `upper_bound` | 取 `estimate` 与 `confirmed_cost` 的较高值，用于最坏情况检验 |

`confirmed` 与 `upper_bound` 口径下，缺少核定值的项目会使方案状态为“暂定（PROVISIONAL）”，而不是“可执行”。两个成本值都会保留在报告里；仅有估算值时，估算即依据，但方案不能声称已核定。

## 2. 资金与预算

- 每条 `funding.csv` 记录是“某来源在某年度的上限”，键为 `(fund_id, year)`；重复键报错。
- 项目只能进入 `allowed_work` 包含其 `work_type` 的资金行，且必须满足 `line.year >= 项目请求年度`。
- 一个项目只占一条资金行。若单项成本超过所有可用单条上限，拒绝原因为 `COST_EXCEEDS_EACH_LINE`，不会假装可以拆到多个来源。
- 行内用量 = 工程成本 + 该行承担的重复开挖成本；用量不得超过 `cap`。
- 报告同时给出“申请成本 / 全部上限”的资金压力比，以及 `within_cap`。

## 3. 依赖与共享施工范围

- `dependencies.csv` 的 `predecessor → successor` 表示 successor 必须在 predecessor 之后。
- 默认规则：predecessor 的年度必须 **严格早于** successor 的年度。仅有同年度资金时，successor 不能计入当年可交付量，拒绝原因为 `PREDECESSOR_NOT_COMPLETED`。
- 显式设置 `allow_same_year_predecessor: true` 时允许同年度，但状态降为“暂定”，并在报告中提示执行部门须保证年度内前置先完成。这是行政判断，工具不替专班作保证。
- `shared_site = true` 的边，如果前置与依赖安排在不同年度，依赖所在资金行额外计入 `repeat_dig_cost`。同年度安排不产生重复开挖。
- 依赖成环、引用未知项目或自依赖均视为输入错误，不形成方案。

## 4. 已签约项目与承诺冲突

- `contracted = true` 的项目是既有承诺。目标函数第一优先级是让已签约项目全部入选。
- 若因资金上限、成本修订或依赖规则无法全部入选，方案状态为 `INFEASIBLE_COMMITMENT`，并逐项列出：成本、可用资金单条上限、缺口、候选资金行、来源行号。
- 执行部门收到的是“冲突 + 受影响承诺”，不是一份看起来完整、实际悄悄删掉签约项目的安排。

## 5. 受益与片区均衡

输入没有“项目 → 民生需求”的直接映射，因此：

- 片区受益 = 该片区是否有项目入选；户数 = 该片区 `confirmed = true` 的需求记录户数之和。
- 同一片区多条已确认需求可能重叠，报告给出 `DEMAND_OVERLAP_ASSUMED` 提示，需按来源记录复核。
- 没有任何已确认需求记录的片区，受益未知；只要有此类片区参与项目，方案状态即为“暂定”。
- 均衡风险码：
  - `UNCOVERED_CONFIRMED_NEED`：有已确认需求的片区没有任何项目入选；
  - `UNCOVERED_WHILE_OTHERS_MULTI_PACKAGE`：上述片区未覆盖，同时其他片区安排了多个小包，存在拆分挤占风险；
  - `DEMAND_UNKNOWN`：部分片区需求口径不完整。

## 6. 策略与批准

工具对同一情景测算四种策略，均以“已签约项目入选数”为第一目标，再按策略目标排序：

| 策略 | 目标（依次比较） |
| --- | --- |
| `benefit`（默认批准） | 已确认受益户数 → 入选项目数 → 成本更低 |
| `cost` | 入选项目数 → 受益户数 → 成本更低 |
| `district` | 覆盖片区数 → 受益户数 → 成本更低 |
| `sequence` | 满足的依赖链数 → 项目数 → 受益户数 |

`approved_strategy` 指定哪一份作为“批准确认方案”；其余策略只用于比较。策略比较表附有与批准方案的差异（新增、退出、年度/来源调整、成本变化、新增冲突）。

## 7. 成本修订与保留当时依据

- 修订写在情景文件 `cost_revisions`，每条必须包含 `project_id`、`confirmed_cost`、`as_of`、`reason`、`source`。缺一项即拒绝加载情景。
- 修订按 `as_of` 排序依次叠加，日志记录 `previous` 与 `updated`，原 CSV 的 `estimate` 与来源行列号始终保留。
- 比较两个情景时，可用 `--before-report` 指定此前冻结的 JSON 报告，从而与“当时批准的依据”比较，而不是与今天的数据比较。
- 输入文件指纹（sha256）写入每份报告，便于核对是否使用了同一批材料。

## 8. 搜索与“非穷尽”标记

组合选择是分支定界搜索，并在开始前用贪心构造一个可行解作为初始下界。

- **主目标精确求解**：已签约项目数、片区受益户数、依赖链完整度（按策略顺序）通过乐观上界剪枝，结果对这些目标是精确的。测试中用独立暴力枚举对随机小规模实例做交叉验证（`tests/test_solver_exactness.py`）。
- **成本只作偏好**：主目标相同时按较低成本优先，但工具不声称全局成本最小；因此“同等主目标”的分支会被剪掉。报告的方法说明会写明这一点。
- **预算**：默认节点上限 300000、墙钟上限 2.5 秒。任一触发即标为 `SEARCH_INCOMPLETE`（状态“未完成”），表示这是已找到的最好安排但未证明主目标最优，不得当作最终可执行方案。可在情景中通过 `search_node_limit` 调整节点上限。

## 9. 什么时候不给可执行方案

以下任一情况，状态为 `INVALID_INPUT`，不运行组合测算：

- 缺少输入文件或字段；
- 关键字段为空（成本、上限、`contracted`、`shared_site` 等）；
- 重复主键、重复资金键、重复需求键；
- 依赖引用未知项目、自依赖或成环；
- 工作类别没有任何资金允许。

状态 `PROVISIONAL` 表示方案可讨论但不可直接执行：存在未核定成本、需求口径未知，或使用了同年度接续假设。
